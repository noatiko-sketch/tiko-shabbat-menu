# רשימת קניות משפחתית

לשונית שלישית באפליקציה הקיימת: רשימה פעילה אחת לכל בני המשפחה, ללא קשר לתאריך תפריט השבת.

- הוספה לפי שם, קטגוריה וכמות חופשית (לא חובה). מוצר חדש נשמר גם במאגר; המאגר מתחיל ריק ולומד מהוספות המשתמשים.
- בחירה חוזרת מהמאגר עם חיפוש וסינון קטגוריה. הוספת שם שכבר קיים אינה יוצרת כפילות; נשמרת הקטגוריה הקיימת. לשינוי קטגוריה משתמשים בעיפרון.
- המוצרים שטרם נקנו מוצגים לפי קטגוריות. סימון נקנה מעביר לאזור נפרד שניתן לפתוח ולבטל בו סימון. מוצר שלא נמצא נשאר ברשימה גם לאחר סגירת האפליקציה ובחנות הבאה.
- ניקוי מסיר רק מוצרים מסומנים, אחרי אישור בתוך המסך. הסרה מהרשימה אינה מוחקת מהמאגר. הוספה חוזרת של מוצר מסומן מחזירה אותו למוצרים שנותרו לקנות.
- שינוי קטגוריה זמין גם ברשימה וגם במאגר ושומר על הכמות ועל סימון הקנייה.

קטגוריות פתיחה: ירקות ופירות, מוצרי ניקוי, קטניות, דגני בוקר, מוצרי חלב, דגים בשר ועוף טריים, מים, קפואים, שימורים וכללי. ברירת המחדל למוצר חדש היא כללי. הוספת קטגוריות נוספות תהיה בהמשך.

## אחסון ושיתוף

השדה `shopping` נוסף בהוספת המוצר הראשון לקובץ המשפחתי הקיים ב־Drive. אין קובץ, אתר או מסד נתונים חדשים. קריאה של רשימת הקניות אינה יוצרת תפריט או משנה נתונים. נשמרים כל שדות התפריט והנתונים האחרים בקובץ.

`lib/shopping.ts` הוא המודל המשותף ללקוח ול־Apps Script. `/api/shopping` משתמש באותו proxy ובאותו חיבור Drive קיים; ללא `TIKO_STORAGE=drive` מוחזרת הודעת חיבור חסר, ללא מעבר למסד חלופי. הזהות, בדיקת מקור הבקשה, סוד החיבור ואימות מזהה הקובץ נשמרים.

כתיבות משתמשות באותו ScriptLock ובקריאה טרייה של הקובץ. לקניות גרסה עצמאית; שינוי מקביל שגורם להתנגשות נדחה בלי לדרוס את השינוי האחר. מזהה פעולה מונע כתיבה כפולה בניסיון חוזר. הלקוח מציג לחיצות מיד ושומר אותן בזו אחר זו; כשל מחזיר לתוצאה האחרונה שאושרה ומבטל פעולות תלויות שלא נשלחו. שגיאות נשארות גלויות. אין שמירה מקומית שמחליפה את המידע המשותף, ואין עבודה לא מקוונת בגרסה הראשונה. נדרש חיבור בזמן שמירה; אין לסגור את האפליקציה כל עוד מוצג ״שומרים…״.

הרשימה מתרעננת כל 30 שניות כשהמסך פעיל, וכן בחזרה למסך או לאחר חזרת הרשת. אין רענון שדורס פעולות ממתינות.

## בדיקות ופרסום

הרצה: `npm run check` ואז `npm run build`. הבדיקות משתמשות בנתונים מומצאים בלבד, כולל הרצת חבילת Apps Script עם Drive ו־ScriptLock מדומים, בדיקות התנגשות, שמירה כפולה, החזרה לאחור ושמירת נתוני התפריט. בדיקת ממשק משתמש נעשתה מקומית עם route זמני בזיכרון, שהוסר לאחר הבדיקה; אין חיבור בדיקות ל־Drive הפעיל.

יש לבנות מחדש את `google/Code.gs` באמצעות `node scripts/build-drive-bridge.mjs` אחרי שינוי במודל הקניות או במעטפת. בקשת המיזוג כוללת כבר את החבילה שנבנתה. לאחר מיזוג, נעה תפרסם את חבילת Apps Script באותו פרויקט ובהגדרות הגישה הקיימות, ואז את ה־main המעודכן לאתר הקיים. העלאה ל־GitHub אינה מפרסמת בעצמה. עדכון האתר ללא עדכון חבילת Google אינו מספיק להפעלת הקניות; חיבור ישן ייכשל עם הודעה גלויה במקום לשמור במקום אחר.

בהוספה ידנית, מהמאגר או מצילום, שם זהה ברשימה (לאחר איחוד רווחים ונרמול אותיות) דורש אישור. ההתראה כוללת גם מוצר שנקנה וכפילות בין שורות שנבחרו מצילום. ביטול אינו משנה את המוצר; אישור מעדכן את אותה שורה ומחזיר אותה למצב שצריך לקנות. הכמות החדשה מחליפה את הישנה ללא סכימה; בחירה מהמאגר ללא כמות משמרת את הכמות הקיימת. מוצר שנמצא רק במאגר אינו גורר התראה.
