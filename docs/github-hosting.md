# טיקו — GitHub Pages וגוגל בלבד

## בחירת האחסון

לפי בקשת נעה אין Vercel ואין אחסון Cloudflare חדש. הממשק הסטטי פועל ב־GitHub Pages. פעולות הנתונים פועלות באותו Google Apps Script ובאותו קובץ Drive. האתר הישן נשאר זמין עד אימות האתר החדש.

## חיבור הממשק

- pages/main.tsx טוען את אותו ממשק React, ללא שרת Next.js.
- הכתובת הציבורית של פריסת גוגל נמצאת ב־google/deployment.json וב־workflow. היא אינה סוד.
- lib/google-transport.ts מנהל חיבור postMessage למסגרת HTML Service של גוגל; google/Bridge.html מקבל רק הודעות מהמקור המוגדר, עם nonce אקראי. תשובות נקשרות לחלון ולמקור המדויקים שהשלימו את החיבור.
- google.script.run מפעיל את pagesRequest, שבודק כניסה ופרופיל משפחתי לפני כל קריאה או כתיבה. מפתח TIKO_BRIDGE_TOKEN נשאר בשרת הישן ובגוגל ואינו מגיע לדפדפן או ל־GitHub Pages.
- תפריט וקניות שומרים על המנוע הקיים, נעילות, גרסאות, מניעת כפילויות ותגובה אופטימית.
- קוד הכניסה המשפחתי, אם הוגדר ב־TIKO_FAMILY_CODE, מוקלד באתר ונשמר בזיכרון העמוד בלבד; הוא אינו נשמר בכתובת או במאגר הקוד. כשאין קוד, נשמרת הגבלת החשבון הקיימת של גוגל.

## פרסום אוטומטי

Settings → Pages → Source: GitHub Actions.

פעולת pages.yml מריצה בדיקות ובניית אתר. שינויים ב־google/Code.gs, ב־google/Bridge.html או בהגדרות הפריסה מפורסמים לגוגל **לפני** החלפת הממשק בפייג׳ז. הקוד מעדכן את אותה פריסה, שומר על אותו URL, ואינו מוחק את Index או את manifest הפרויקט.

את מזהה פרויקט גוגל שומרים במשתנה ריפו TIKO_GOOGLE_SCRIPT_ID, ולא בקוד הציבורי.

לפרסום אוטומטי של קוד גוגל, מגדירים פעם אחת Repository secret בשם GOOGLE_SCRIPT_OAUTH, המכיל JSON עם client_id, client_secret ו־refresh_token של הרשאת OAuth לחשבון בעלת הפרויקט. נדרשים תחומי script.projects ו־script.deployments והפעלת Apps Script API בחשבון ובפרויקט OAuth. אין לשלוח את הערכים בצ׳אט או לשמור אותם בקובץ בריפו. GitHub Actions משתמש בהם רק בענף main; בקשות מיזוג אינן מקבלות אותם.

התקנה ראשונית ידנית נתמכת: לאחר פרסום ואימות של אותו קוד גוגל, מפעילים Run workflow עם google_already_deployed=true. אחרי כן שינויים בממשק בלבד מתפרסמים אוטומטית גם ללא סוד OAuth. שינוי עתידי בבקנד נחסם עד שהרשאת גוגל מוגדרת, כדי לא לפרסם ממשק מול שרת שאינו תואם.
