# אוכל לשבת — משפחת טיקו

אפליקציה משפחתית לתפריט שבת, מאגר מנות, מתכונים, שיבוץ מי מכין מה ורשימת קניות משותפת.

בלשונית **רשימת קניות** מוסיפים מוצרים עם קטגוריה וכמות לפי הצורך. כל מוצר נשמר במאגר המשפחתי לבחירה חוזרת. מסמנים מה נקנה; מוצרים שלא נמצאו נשארים ברשימה. אפשר לבטל סימון, לנקות רק מוצרים שנקנו ולשנות קטגוריה דרך סמל העיפרון ברשימה או במאגר, למשל מכללי לשימורים. [פרטי הפיתוח והפרסום](docs/shopping-list.md).

כפתור **צלם רשימה** מאפשר לפענח צילום של רשימה כתובה ולתקן את המוצרים, הכמויות והקטגוריות לפני הוספה. מוצרים עם ✓ או קו על השם מוצגים אך אינם נבחרים אוטומטית. היכולת דורשת הגדרת שירות הפענוח בחשבון בעלת האתר; [הפעלה ומגבלות](docs/shopping-photo-import.md).

**האתר הפעיל:** https://tiko-shabbat-menu.noatiko.chatgpt.site

## איך עובדים יחד — שלושה צעדים

1. פותחים את המאגר הזה ב־Codex/ChatGPT עם חשבון GitHub אישי ומבקשים את השינוי.
2. מבקשים לשמור את השינוי בענף נפרד ולפתוח בקשת מיזוג (Pull Request). בודקים את התוצאה ומחכים שבדיקת `Check` תהיה ירוקה.
3. מאחדים ל־`main`. נעה מבקשת מהחשבון שלה לפרסם את הקוד המעודכן לאתר הקיים.

נוסח שאפשר להדביק לצ׳אט של כל אחד:

> עבוד על המאגר המשפחתי הזה. קרא תחילה את AGENTS.md. צור ענף לשינוי שלי, בדוק אותו ופתח בקשת מיזוג. שמור על האתר ועל הדאטה הקיימים.

נוסח לפרסום בחשבון של נעה:

> סנכרן את main העדכני מהמאגר המשפחתי אל קוד אתר טיקו הקיים. בדוק את ההבדלים מול הגרסה הפעילה לפני המיזוג, שמור גם שינויים שטרם הגיעו מ־Sites ל־GitHub, הרץ בדיקות ופרסם באותו project_id ובאותו קישור. אל תיצור אתר או מאגר נתונים חדשים. עדכן את GitHub בכל תיקון שנוסף בזמן הפרסום.

העלאה ל־GitHub אינה מפרסמת לאתר בעצמה. הבדיקות אוטומטיות; הפרסום נשאר דרך החשבון בעל האתר, כדי לא להוסיף כרגע שירותי אחסון, מפתחות וחשבונות. שינוי בבקנד עשוי לדרוש גם עדכון פריסת Apps Script, לאחר בניית `google/Code.gs` מהמקור המשותף.

## איפה הנתונים?

הנתונים הפעילים נשארים בקובץ המשפחתי המקורי ב־Google Drive. השרת של האתר פונה אליו באמצעות Google Apps Script. אין צורך במסד נתונים חדש.

GitHub משתף קוד; הוא אינו מעניק הרשאות ל־Drive, ל־Apps Script או לפרסום ב־Sites. את הרשאות הניהול האלה משתפים בנפרד לפי הצורך. פיתוח רגיל ובדיקות אינם דורשים את המפתח של המאגר הפעיל.

## בדיקות ופיתוח

נדרש Node.js 24 ו־pnpm בגרסה שב־package.json.

```sh
pnpm install --frozen-lockfile
npm run check
npm run dev
```

`npm run check` בודק טיפוסים, מריץ את בדיקות הבקנד והממשק הלוגי, ומוודא שהקוד שנבנה לגוגל תואם למקור. GitHub מריץ גם בניית אתר. הבדיקות משתמשות בנתונים מבודדים ואינן ניגשות ל־Drive הפעיל.

הוראות פיתוח מפורטות: [docs/local-development.md](docs/local-development.md).

## כללים פשוטים

- ענף אחד לכל שינוי; מתחילים מה־main העדכני.
- משאירים את הנתונים האמיתיים מחוץ לבדיקות.
- לא מעלים סיסמאות, מפתחות או קובץ state.json מה־Drive.
- לא מפרסמים שני עדכונים לאתר במקביל.
- שינוי שמגיע ישירות דרך Sites צריך לחזור גם למאגר GitHub לפני השינוי הבא.
